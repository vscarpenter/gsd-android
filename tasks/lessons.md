# Lessons

- **AGP 9.x has built-in Kotlin:** applying `org.jetbrains.kotlin.android` is a hard error. Android modules get Kotlin from AGP itself; `kotlin { jvmToolchain(17) }` still configures the toolchain, and the Compose compiler plugin (`org.jetbrains.kotlin.plugin.compose`) is still applied explicitly. Pure-JVM modules keep `org.jetbrains.kotlin.jvm` as before.
- **KSP dropped Kotlin-coupled versions:** releases are now standalone (`2.3.x`), Kotlin-version-independent. Don't look for `"<kotlin>-<ksp>"` tags anymore.
- **Stale cmdline-tools can't see new SDK packages** ("SDK XML version 4" warning → "package contains no system images"). Fix: `sdkmanager --install "cmdline-tools;latest"` and use the freshly installed copy (it lands in `latest-2` if `latest` is in use).
- **A system-image directory can exist but be broken** (metadata only, no `system.img`). `avdmanager` then reports "contains no system images", and the emulator reports "No initial system image for this configuration". `sdkmanager --install` is a no-op here, because the surviving `package.xml` makes the package look installed. Run `sdkmanager --uninstall "<package>"` first, then `--install`, and check for `system.img` rather than for the directory. On 2026-09-20 every `.img` file in the `google_apis` image vanished mid-session and nothing else did. The `google_apis_playstore` image shows the same damage, with a directory change dated 2026-05-01. The cause is unknown.
- **Compose `FontVariation` API needs `@OptIn(ExperimentalTextApi::class)`** (file-level opt-in) for variable-font weight settings.
- **`avdmanager create avd` without `-d <device>` yields a 320×640 legacy profile** — fine for instrumented tests, misleading for adb tap coordinates and screenshots. Check `dumpsys input_method` served-view bounds when adb taps mysteriously miss.
- **`jvmToolchain(17)` + Homebrew-only JDK breaks IDE sync:** Gradle toolchain detection doesn't scan Homebrew kegs, so CLI builds pass (daemon *runs on* the Homebrew 17) while Android Studio (daemon on JBR 21) can't find a 17. Fix: the `org.gradle.toolchains.foojay-resolver-convention` settings plugin, which lets Gradle auto-provision a matching JDK into `~/.gradle/jdks`. Verify IDE-shaped failures by re-running with `JAVA_HOME` pointed at Studio's JBR.
- **A `ComposeTestRule` sets content once per test:** a second `setContent` in the same test throws, so a test that wants two different compositions (loading vs loaded, empty vs populated) is two tests. Split it rather than reaching for a mutable state hoisted outside `setContent`.
- **`clearAndSetSemantics` hides the child text from `onNodeWithText`:** the whole point is to replace the merged subtree with one spoken label, so a finder looking for the visible string finds nothing. Assert the `contentDescription` instead — or, better, pin the value through a pure helper (`legendValue(stat)`) in a JVM test and leave the instrumented test to check that the node exists.
- **A dropdown item and the row that opens it collide in `onNodeWithText`:** the trigger row shows the current selection, so the same label matches twice once the menu is open. Scope the finder to the popup — `onNode(hasText(label) and hasAnyAncestor(isPopup()))` — rather than adding a test tag to production code.
- **A Kotlin default argument may reference a *later* required parameter.** Defaults are evaluated at the call site in declaration order of *use*, not of position, so `tasks: List<Task>? = null` sitting after required params, or a default that reads a parameter declared below it, compiles fine. A claim to the contrary cost a needless signature reshuffle this round — verify a suspected compiler constraint against an actual build before designing around it.
- **A trailing lambda binds to the *last* function-typed parameter**, not to the one you meant. When a composable takes two lambdas, pass the earlier one positionally (or by name) and keep the trailing block for the last — otherwise the arguments silently swap and the failure surfaces as a mis-wired callback, not a compile error.
- **With a physical phone attached over wireless ADB, pin the instrumented run:** `ANDROID_SERIAL=emulator-5554 ./gradlew connectedAndroidTest`. Without it Gradle installs the debug build on the phone, which is both slow and destructive to real data. `adb devices -l` first, every session.
- **INTERNET permission is invisible until the first real socket:** signed-out flows and JVM-hosted network tests (MockWebServer) never exercise it on device, so a missing `<uses-permission INTERNET>` survived five phases. Pair every silent failure hunt with `dumpsys package <pkg> | grep -A6 "requested permissions"`. And never ship `catch (_: Exception) {}` — the swallowed exception hid this for exactly one tap-that-does-nothing bug report.
- **An empty remote listing proves nothing without a confirmed owner.** PocketBase list rules filter rows, so a guest request answers 200 with zero items, and `BoundedListing` accepts that as complete. Anything destructive that reads "absent remotely" must confirm the owner in the same run (`SyncRemote.confirmIdentity`, auth-refresh based). Review finding S1 (2026-09-20) was this gap in `reconcileDeletions`.
- **Run instrumented tests on `gsd-test`, never `gsd-shot`.** A connected run installs and then uninstalls the app, which would wipe the seeded screenshot data on `gsd-shot`. The first connected run right after an emulator boot can fail at install; a second run succeeds.
- **Coordinator tests must join before they close the database.** `scope.cancel()` is cooperative, so a cancelled Room call can still land after `db.close()`. The `IllegalStateException` then fails whichever test runs next. Use `scope.coroutineContext.job.cancelAndJoin()` in `tearDown`.
- **Set the explaining flag before the flag observers wait on.** `signedIn = false` followed by `sessionExpired = true` lets an observer see "signed out" without the reason. A test that awaited the first flag and read the second failed about one run in three. Order state writes so any observed combination is valid.
- **A test that leaves a screen must prove it came back.** The first S4 palette test passed against broken code, because the tab tap that should have returned to Matrix silently did nothing (review finding 43). Wait on the selected tab before asserting that something is absent, and watch every absence assertion fail on the old code first.
- **A touch click lands on whatever covers the node's center.** On the 320x640 `gsd-test` screen a bottom sheet covers the center of its own scrim, so `performClick()` on "Close sheet" hits the sheet. Use `performSemanticsAction(SemanticsActions.OnClick)`.
- **The v1 compose test rules run effects inline.** An effect that calls `navigate` can then run before a `Scaffold` has composed its `NavHost`, which fails with "Navigation graph has not been set". Activity tests that start from a deep link need the `junit4.v2` rules, which queue effects as production does.
- **A non-inclusive `popUpTo` with `saveState` files the saved stack under the `popUpTo` target.** Add `restoreState` to the same call and a screen pushed over the start destination comes straight back. Ordinary tab switching escapes only because its first pop saves nothing (review finding 43). The fix: going to the start destination is `popBackStack(start, inclusive = false, saveState = true)`, never `navigate` (`nav/TabNavigation.kt`). Send every top-level route through that one helper.
- **`launchSingleTop` on the visible destination swaps its entry for a copy, and the copy can stay at CREATED.** Every `collectAsStateWithLifecycle` and `repeatOnLifecycle` on that screen then goes silent: state changes, the UI does not. In `NavController.navigate` the `launchSingleTop` branch only runs when the restore branch does not, so changing `restoreState` can expose it. `TabNavigationLifecycleTest` pins the entry at RESUMED on a stub `NavHost`.
- **Run the whole suite before trusting a navigation change.** The targeted tests for finding 43 were green while the app was broken. A test from the previous fix caught it, because it happened to close a sheet after a deep link.
- **Prove a guard test by mutation.** A test that pins existing behavior passes on the first run, which proves nothing. Break the behavior on purpose, watch the test fail, and revert.
- **Wait for the state a test is about, not for the screen.** The doubled Matrix entry arrives a moment after the first frame. A Back press sent too early passes against broken code. Wait on `pendingRoute` clearing first.
- **Shared UI requests are events, not state.** A `StateFlow` replays its value to every new collector, and a composition restarts its collectors on every tab switch and rotation. Use `OneShotRequest` (claim with `compareAndSet`) and consume through `ConsumeWhileStarted`.
- **Validate what the user types, where they type it.** A state change to a stored task must never reject it, because sync can deliver a task that breaks a local limit. iOS counts characters, while the web and Android count UTF-16 units, so one emoji is enough. Use `TaskStore.change`, `duplicate`, or an intent method for state changes. Keep `add` and `update` for typed input (review finding S6).
- **Check the siblings before trusting the spec on shared behavior.** Spec 7.11 said "every write path", and Android followed it. Neither the web nor iOS validates on a state change. When two shipped clients agree and the spec disagrees, the spec is the outlier.
- **An uncaught exception in `viewModelScope` kills the instrumentation process.** The run ends with "Process crashed" and the later tests never run. That is a faithful reproduction of a user-facing crash, and it is why a view model test for a crash bug belongs in its own targeted run while red.
- **Write the reproduction before the design question.** A failing test that holds under every candidate design costs nothing to keep, and it turns the design proposal from an opinion into evidence.
- **A Back key in a test depends on two things the test does not own.** A text field that takes focus in a dialog raises the soft keyboard, and Back then hides the keyboard and leaves the dialog open. A key sent while a closing dialog is still handing input focus back is dropped. Prefer a semantics action. When the test is about Back itself, wait for `mInputShown=false` in `dumpsys input_method` and for `Activity.hasWindowFocus()`.
- **A test that has passed for a day can still be a race.** `PaletteRequestsTest` went from passing every run to failing every run once the keyboard process was warm. Timing the test does not control is luck, in either direction.
- **An activity's window insets do not report a keyboard that belongs to a dialog's window.** Ask the system instead: `uiAutomation.executeShellCommand("dumpsys input_method")`.
- **Shell calls in diagnostics change the timing they are measuring.** Two `dumpsys` calls before a key press hid the race for six runs. Log cheap in-process facts before the event and the expensive ones after it.
- **Read inside the transaction you write in.** `get(id)` followed by `withTransaction { write }` lets two callers act on the same stale read. Room runs transactions one at a time, so a read inside one is the ground truth. Eight concurrent completes spawned eight instances until `setCompleted` moved its read (review finding S5).
- **A state setter should do nothing when the state already matches.** Writing anyway restamps `updatedAt`, queues a push, and can win last-write-wins over a newer edit made elsewhere. It also overwrites facts like `completedAt`. Compare first, then write.
- **Make a race test fail on purpose.** Two concurrent calls can pass by luck against broken code. Eight made the red run certain.
- **A green review check can mean that no review ran.** The Claude review workflow finished in 15 seconds with 5 turns on four of seven pull requests, because its `--allowedTools` denies the plugin's first `gh` call. Read `num_turns` and `duration_ms` in the run log before you trust a clean result. A real review here took 6 to 9 minutes.
- **Stacked pull requests merge cleanly with merge commits.** Base each PR on the branch below it, so each diff and each review covers one change. Merge bottom-up, retarget the next PR to `main`, and wait until `mergeable` leaves `UNKNOWN`. A squash or a rebase would change the SHAs and force a rebase of everything above.
- **STARTED does not mean the user can see it.** A covered activity stays STARTED until the new one is up, so a STARTED gate lets the hidden instance win a race with the visible one. When two instances can exist, scope shared requests to the instance, or gate on RESUMED.
- **A fix made under review needs its own red test, and the test needs rechecking after the next fix.** My stale-cursor test built its state with `LocalErase`. The next commit made `LocalErase` clear the cursor, and the test passed with the code under test deleted. Build the state directly, and prove the test by removing the line it guards.
- **The cursor belongs to the data it describes.** A pull cursor means "everything up to here is on this device". Any code that erases the tasks must clear the cursor in the same transaction, or a later step can be skipped and leave a wiped device that never pulls its history again.
- **`singleTop` is not enough when another page can sit above the activity.** The sign-in Custom Tab runs in GSD's task, above `MainActivity`. `singleTop` reuses an activity only at the top of its task, so the OAuth callback would still stack a copy. `singleTask` closes what is above and hands the link to the one instance (review finding 4).
- **Test a launch mode by counting instances.** `ActivityLifecycleMonitorRegistry` lists every live activity by stage. Wait for either outcome: a second copy, or the handled link. The red run then fails on `expected 1 but was 2`, not on a timeout.
- **Static shortcuts restart the task.** `dumpsys shortcut` shows `flg=0x1000c000` on both: `NEW_TASK`, `CLEAR_TASK`, and `TASK_ON_HOME`. They never reach `onNewIntent`, they discard an open draft, and the app cannot change those flags.
- **Check every caller before wiring a dead control.** The "..." button had an empty lambda, and three of the six surfaces that draw a card had no menu to open. A control with nothing behind it should not be drawn (review finding 1).
- **An `else` in a `when` over an enum hides the value you forgot.** `SwipeTaskRow` gave the resting state the red delete background that way, and Trash drew its text on it (review finding 2). Name every value, and let the compiler ask about the next one.
- **A pixel test needs content that paints nothing.** An opaque card hid the resting background on Matrix. `captureToImage().toPixelMap()` over a bare `Spacer` showed it in one run. Read the expected colors from the theme inside the composition.
- **Mutate to the design you rejected.** My tests for `singleTask` all passed under `singleTop`, so nothing guarded the choice. A reviewer saw it by reading. One mutation run would have shown it too (review of #13).
- **A review that posts nothing has not passed.** Check `num_turns` and `permission_denials_count` in the run log. 27 turns with 11 denials and no comment means the verdict is unknown, so get another review.
- **`confirmValueChange` is a question, not an event.** Material asks it on every drag frame, so an action placed there ran 8 or 9 times per swipe (review finding 3). Run swipe actions in `onDismiss`, then call `state.reset()`.
- **Count the calls before you trust a cause.** The review said "fires twice". A counter said 8. The count took one test run, and it exposed the completion path as well.
- **Say so when a test never went red.** A test that passes on the old code can still guard a path, if a mutation proves it. It is not proof of the fix, and its KDoc should say which test is.
- **A copied method is a list of the ones nobody copied.** `BrowseViewModel` had its own `toggleCompleted` and no other row operation, so two screens showed an eight-item menu with six dead items (review finding 48). Move shared operations into one view model that each screen creates, as `TaskEditorViewModel` already was.
- **Default no-op callbacks hide missing wiring.** `TaskRowActions` defaults every action to `{}`, so a screen that forgot six of them compiled and looked complete. A test that taps each item against the real store is what caught it.
- **Cleanup after a suspending call belongs in `finally`, and it must know what it is cleaning.** A cancelled `LaunchedEffect` skips the code after `showSnackbar`, so its record outlived it. A plain `finally` then cleared the record a newer delete had just written. Clear with `compareAndSet(shown, null)`.
- **Test a reviewer's fix like any other code.** The suggested `finally` fixed the bug it named and broke a second delete. One guard test, written first, showed it in one run.
- **Read the whole file before you cite a sibling.** I quoted one line of `TaskListRow.swift` to say iOS has no menu in select mode. Line 48 keeps the long-press menu.
- **Order the early returns by what may override what.** `ReminderPlanner` returned on `notificationSent` before it read the snooze, so a snooze could never override a posted reminder (review finding 5). Compute the overriding value first, then apply the gate it overrides.
- **When the spec names a mechanism, use it.** Spec 11.2 said a reminder tap is the `gsd://task` link. The code sent an extra on a second path that skipped the router's navigation, so the tap worked only on Matrix (review finding 47). A second path into the same place drifts from the first.
- **An editor holds three versions of a row, so Save is a three-way merge.** The row it opened, the row the user edited, and the row now in the store. Writing the edited row whole undid a completion made from the reminder (review finding 44). Take the user's value only where it differs from the opened row, and read the stored row inside the write's transaction.
- **Declare `: Unit` on a test written as `= runBlocking { }`.** The block returns its last expression, and JUnit 4 refuses a test method that is not void. The run dies with `initializationError`, which names no test.
- **Mutate the plumbing, not only the behavior you came to fix.** My tests for `TaskStore.edit` covered the race, validation, and a vanished task. With the sync queue insert deleted they all passed (review of #22). After the red-green cycle, delete each side effect once and see which test complains.
- **One rule over N fields wants a table.** `EditorRules.merge` applies one rule to twelve fields, and four sample tests left eight unguarded. Drive the rule over every field and put the field's name in the failure message.
- **Quote a string from `strings.xml`, never from its resource name.** `task_not_found` reads "That task no longer exists".
- **A `StateFlow` is a bad carrier for events with equal payloads.** It skips a value equal to the last one its collector saw. A second `Unit` sent while a handler ran was never delivered (review finding 45). Wrap each event in its own object, or use a channel.
- **Prefer the fix you can write a test for.** Forbidding a suspending handler would have hidden the bug behind the type system with nothing to pin it. Removing the equality left a test that fails on the old code.
- **Check a PR's state before you push to its branch.** On 2026-09-20 three PRs merged while their review follow-ups were still running gates. GitHub deletes the branch on merge, so the next push made it again with commits that were not on `main`. Run `gh pr view <n> --json state` first. If it merged, confirm `git diff <base> origin/main` is empty and open a new PR to `main`.
- **Fix a branch in the middle of a stack from a separate worktree.** `git worktree add <scratch> <branch>` leaves the main tree alone, which matters when reviewers or a build are reading it. `git merge-tree --write-tree` then shows whether the branches above still merge cleanly.
- **Open the lines a finding cites, even when the finding is yours.** Finding 49 cited iOS swipes at `SmartViewListView.swift:110-123`. Those lines swipe a smart view link, not a task row. The right file agreed with the conclusion, so nothing broke. A citation can name the right file and the wrong thing.
- **A search screen shows the query twice.** Once a test types a task's title into a search field, `onNodeWithText(title)` matches the field and the row. Match the row with `hasText(title) and !hasSetTextAction()`.
- **Read the spec section before you move the code it describes.** I lifted the celebration out of `MatrixScreen` and carried a Phase 1 mismatch with it, then pinned the mismatch in a new test (review finding 51). A move is the cheapest moment to find that the code never matched.
- **An idle wait on an advancing test clock runs a finite animation to its end.** A finder that looks for the confetti after a tap finds nothing, and an absence check passes with nothing to see. Set `mainClock.autoAdvance = false` before the action and step frames with `advanceTimeByFrame()`.
- **Make the shared builder require what every screen must do.** `taskRowActions` takes the celebration with no default, so a new screen cannot forget it. This is the fix for "default no-op callbacks hide missing wiring".
- **Build the seam under green, then write the red test against it.** A test needs something to observe. Swap in the replaceable API first with no behavior change, run the old tests, and only then write the test that fails.
- **Every path into an action needs its own guard.** On Matrix a disc tap goes through the menu builder, and a swipe goes through the screen's own toggle. Tests on the first left the second unpinned. I saw the gap by reading the call sites, and a mutation proved the guard I added.
- **Check the sibling before you file a finding from the spec.** I raised finding 52 from one spec line ("or bulk bar, always with confetti") without opening iOS. iOS's bulk bar celebrates nothing, and the web has no bulk bar, so the spec line was the outlier and the finding closed as a doc fix. When only one sibling has the surface, that sibling decides.
- **A paused activity is still STARTED.** Android pauses the old activity before it creates the new one and stops it after the new one resumes. In that window a STARTED gate still collects, so two copies can both take a shared request. Gate a shared-request consumer on RESUMED (review finding 46).
- **Wait for the fresh copy by identity, not by count.** After `CLEAR_TASK`, "one live activity" is true before the new copy exists and after the old one dies. Capture the instance the scenario launched and wait for a single live activity that is not it.
- **Commit before you mutate, or restore by reversing the edit.** `git checkout -- <file>` after a mutation restores the committed version, which undid the uncommitted fix under test. A hash check before and after each mutation catches it.
- **Say which test proves which line.** The route gate had its proof in the activity tests. The consumer gate did not, because a dispatch race went the right way three times. Recording that keeps the next person from trusting the wrong test.
- **Check a Compose API against the BOM's version, not against androidx-main.** The main branch runs ahead of any BOM: on 2026-09-24 it was Compose UI 1.13, while BOM 2026.06.00 is 1.11. `hintText` semantics looked perfect in the source and arrived in 1.13. The release notes at developer.android.com say which version added an API; read them before building on it.
- **A hint beside a `BasicTextField` does not name it.** TalkBack reads the hint as loose text and the field as an unnamed edit box. A text field merges what its decoration box holds, so the hint goes inside the box, the way Material's own fields name themselves. An invisible name does not work: a zero-size node never reaches the accessibility tree, and an alpha-0 node counts as hidden.
- **Semantics on one layout node become one node.** A card's custom actions must sit in the card's own modifier chain, beside its `combinedClickable`. On a wrapping `Box` they belong to a node TalkBack never focuses.
- **Android collapses runs of whitespace in a string resource** unless the string is in double quotes. The capture placeholder's spaced-out markers read as single spaces.
- **Keep the fast gate fast when a test needs volume.** A 10,000-task import took 0.9 s and doubled the `:core:model` run. The cap counts rows before it decodes any, so empty rows test the same boundary in 0.16 s.
- **A backfill rule has to cover the row an older build edited, not just the row it pulled.** The Saved backfill merged same-version rows, and its test started with the row already merged. A row edited on 0.10.0 is newer than the server, so it was skipped and pushed `saved_at: ""`. Write the upgrade test from the old build's state, and run it once on a real server with a real `adb install -r`.
- **Seed end-to-end rows with a stamp in the past.** A stamp ahead of the device clock makes every local edit lose last-write-wins, and the run looks like the feature does nothing. A hardcoded time cost one full run on 2026-10-31.
- **Don't edit a checkout while its gates run.** Use a scratch worktree for anything exploratory, and afterward check the result XML to see which tests the run contained.
- **Compare the order of a sync run, not only its rules.** The web pushes and then pulls, and native clients pull and then push, so the same clamp rule gives different results on a queued edit (`S-AND-02`). The same goes for the reads inside a step: Android read the queue before the tasks, and iOS's comment explains why that's backward (`S-AND-03`).
- **Run a server check against the deployment you mean.** The Docker image loads the repo's hooks and the hosted service doesn't (web ADR 0016). Repeat the check on the same binary with no hooks, and say which results depended on a hook.
- **Reading a PR's state doesn't check it unless the command acts on the answer.** On 2026-10-31 a script printed `MERGED` and pushed anyway, recreating a deleted branch, and the description edit next to it went to the merged PR. An earlier lesson already warned about this. Gate the push on the state in the same command, and treat a new push after a long gate run as a fresh decision.
- **An empty `LazyColumn` measures to its minimum size.** `weight(1f)` fills the height and leaves the width at 0, so a pull or drag from an empty list hits nothing. Add `fillMaxWidth()`. The red test with `weight` alone found it.
- **A merge on GitHub and a local merge of the same commits make a criss-cross.** The PR then shows as conflicting with extra files, though `git merge` is clean and the tree doesn't change. Merge `main` forward once more, and wait for GitHub to recompute before calling it clean.
- **Uppercase captions need their words in semantics.** A short word in capitals can be read letter by letter, so a heading drawn as "TAGS" should expose "Tags" (`SectionHeading`). A test that matched the capitals then needs the new text, and a finder on a word like "Snooze" can meet a heading of the same name.
- **A card merges its children's semantics, so look for a child in the unmerged tree.** A test that asserts a tag is absent in the merged tree passes whether or not the tag exists. Use `useUnmergedTree = true` for both the presence and the absence check, or the negative test proves nothing.
- **`clearAndSetSemantics` wipes modifiers placed after it.** A `testTag` added after it vanishes. Set the tag inside the same block (`testTag` from `androidx.compose.ui.semantics`, aliased so it doesn't clash with the platform one).
- **`connectedAndroidTest` uninstalls the app when it finishes, which deletes any file the test wrote.** To pull a screenshot, install both APKs and run `adb shell am instrument -w -e class <Test> <pkg>.test/androidx.test.runner.AndroidJUnitRunner`, then pull before you uninstall. The `class` argument takes one class, not a comma list.
- **A stacked branch can predate `main`.** `docs/due-time-corpus` was cut before Saved landed, so its `ReminderPlanner` lacked `isSaved` and editing it there would have reverted the check. Run `git diff origin/main -- <file>` on any file you are about to change before you build on a stacked base.
- **`merge.ff=only` is set in this repo, so a plain `git merge origin/main` aborts as "Not possible to fast-forward".** Inside a `cmd 2>&1 | tail` pipeline the chain kept going, and a gate ran on the unmerged tree. Pass `--no-ff` for a forward merge, and check `git log -1 --merges` before trusting the run.
- **`gsd-test` is gone; the test AVD is `gsd-e2e` (Pixel 7 profile, API 36).** `emulator -list-avds` on 2026-11-06 showed only `gsd-e2e` and `gsd-shot`. The 0.10.1 and 0.10.2 gates already ran on `gsd-e2e`. `gsd-shot` still holds seeded screenshot data, so the rule stands: never run a connected suite there.
- **`--tests` only works on a plain `Test` task.** `:core:sync` and `:core:store` are Android library modules, so their JVM suites are `:core:sync:testDebugUnitTest --tests '<class>'`; `:core:model` keeps `:core:model:test --tests`.
- **Two `private` top-level classes with one name in one package fail to compile across files.** Both `androidTest` files declared `private class MemoryTokenStore`, and Kotlin reported "Redeclaration". Give each file's fake its own name, or share one `internal` fake.
- **Copy a sibling's mechanism as a pair, not a half.** The web clears its queue at sign-out and seeds every task at sign-in. Android's queue is its seed and a same-owner sign-in seeds nothing (spec 8.21), so clearing at sign-out alone would lose edits made offline before it. B-56 drops the `DELETE` rows at sign-in instead, which reaches the same outcome.
- **A fixture must meet the rule's precondition, or it pins the wrong behavior.** `TrashStoreTest`'s abandon case seeded pending rows and expected the task trashed, while the ABANDON verdict applies only to failed rows. Enforcing the precondition inside the transaction broke the test, not the code.
- **An import removed on one branch and used on another compiles on each and fails once both merge.** The fence branch dropped the coordinator's `SyncOp` import; the B-56 branch uses `SyncOp` in another function. The second branch spells the name in full so the merged file still compiles.
