# Lessons

- **AGP 9.x has built-in Kotlin:** applying `org.jetbrains.kotlin.android` is a hard error. Android modules get Kotlin from AGP itself; `kotlin { jvmToolchain(17) }` still configures the toolchain, and the Compose compiler plugin (`org.jetbrains.kotlin.plugin.compose`) is still applied explicitly. Pure-JVM modules keep `org.jetbrains.kotlin.jvm` as before.
- **KSP dropped Kotlin-coupled versions:** releases are now standalone (`2.3.x`), Kotlin-version-independent. Don't look for `"<kotlin>-<ksp>"` tags anymore.
- **Stale cmdline-tools can't see new SDK packages** ("SDK XML version 4" warning → "package contains no system images"). Fix: `sdkmanager --install "cmdline-tools;latest"` and use the freshly installed copy (it lands in `latest-2` if `latest` is in use).
- **A system-image directory can exist but be broken** (metadata only, no `system.img`). `avdmanager` then reports "contains no system images", and the emulator reports "No initial system image for this configuration". `sdkmanager --install` is a no-op here, because the surviving `package.xml` makes the package look installed. Run `sdkmanager --uninstall "<package>"` first, then `--install`, and check for `system.img` rather than for the directory. On 2026-09-20 every `.img` file in the `google_apis` image vanished mid-session and nothing else did. The `google_apis_playstore` image shows the same damage, with a directory change dated 2026-05-01. The cause is unknown.
- **Compose `FontVariation` API needs `@OptIn(ExperimentalTextApi::class)`** (file-level opt-in) for variable-font weight settings.
- **`avdmanager create avd` without `-d <device>` yields a 320×640 legacy profile** — fine for instrumented tests, misleading for adb tap coordinates and screenshots. Check `dumpsys input_method` served-view bounds when adb taps mysteriously miss.
- **`jvmToolchain(17)` + Homebrew-only JDK breaks IDE sync:** Gradle toolchain detection doesn't scan Homebrew kegs, so CLI builds pass (daemon *runs on* the Homebrew 17) while Android Studio (daemon on JBR 21) can't find a 17. Fix: the `org.gradle.toolchains.foojay-resolver-convention` settings plugin, which lets Gradle auto-provision a matching JDK into `~/.gradle/jdks`. Verify IDE-shaped failures by re-running with `JAVA_HOME` pointed at Studio's JBR.
- **A `ComposeTestRule` sets content once per test:** a second `setContent` in the same test throws, so a test that wants two different compositions (loading vs loaded, empty vs populated) is two tests. Split it rather than reaching for a mutable state hoisted outside `setContent`.
- **`clearAndSetSemantics` hides the child text from `onNodeWithText`:** the whole point is to replace the merged subtree with one spoken label, so a finder looking for the visible string finds nothing. Assert the `contentDescription` instead — or, better, pin the value through a pure helper (`legendValue(stat)`) in a JVM test and leave the instrumented test to check that the node exists.
- **A dropdown item and the row that opens it collide in `onNodeWithText`:** the trigger row shows the current selection, so the same label matches twice once the menu is open. Scope the finder to the popup — `onNode(hasText(label) and hasAnyAncestor(isPopup()))` — rather than adding a test tag to production code.
- **A Kotlin default argument may reference a *later* required parameter.** Defaults are evaluated at the call site in declaration order of *use*, not of position, so `tasks: List<Task>? = null` sitting after required params, or a default that reads a parameter declared below it, compiles fine. A claim to the contrary cost a needless signature reshuffle this round — verify a suspected compiler constraint against an actual build before designing around it.
- **A trailing lambda binds to the *last* function-typed parameter**, not to the one you meant. When a composable takes two lambdas, pass the earlier one positionally (or by name) and keep the trailing block for the last — otherwise the arguments silently swap and the failure surfaces as a mis-wired callback, not a compile error.
- **With a physical phone attached over wireless ADB, pin the instrumented run:** `ANDROID_SERIAL=emulator-5554 ./gradlew connectedAndroidTest`. Without it Gradle installs the debug build on the phone, which is both slow and destructive to real data. `adb devices -l` first, every session.
- **INTERNET permission is invisible until the first real socket:** signed-out flows and JVM-hosted network tests (MockWebServer) never exercise it on device, so a missing `<uses-permission INTERNET>` survived five phases. Pair every silent failure hunt with `dumpsys package <pkg> | grep -A6 "requested permissions"`. And never ship `catch (_: Exception) {}` — the swallowed exception hid this for exactly one tap-that-does-nothing bug report.
- **An empty remote listing proves nothing without a confirmed owner.** PocketBase list rules filter rows, so a guest request answers 200 with zero items, and `BoundedListing` accepts that as complete. Anything destructive that reads "absent remotely" must confirm the owner in the same run (`SyncRemote.confirmIdentity`, auth-refresh based). Review finding S1 (2026-09-20) was this gap in `reconcileDeletions`.
- **Run instrumented tests on `gsd-test`, never `gsd-shot`.** A connected run installs and then uninstalls the app, which would wipe the seeded screenshot data on `gsd-shot`. The first connected run right after an emulator boot can fail at install; a second run succeeds.
- **Coordinator tests must join before they close the database.** `scope.cancel()` is cooperative, so a cancelled Room call can still land after `db.close()`. The `IllegalStateException` then fails whichever test runs next. Use `scope.coroutineContext.job.cancelAndJoin()` in `tearDown`.
- **Set the explaining flag before the flag observers wait on.** `signedIn = false` followed by `sessionExpired = true` lets an observer see "signed out" without the reason. A test that awaited the first flag and read the second failed about one run in three. Order state writes so any observed combination is valid.
- **A test that leaves a screen must prove it came back.** The first S4 palette test passed against broken code, because the tab tap that should have returned to Matrix silently did nothing (review finding 43). Wait on the selected tab before asserting that something is absent, and watch every absence assertion fail on the old code first.
- **A touch click lands on whatever covers the node's center.** On the 320x640 `gsd-test` screen a bottom sheet covers the center of its own scrim, so `performClick()` on "Close sheet" hits the sheet. Use `performSemanticsAction(SemanticsActions.OnClick)`.
- **The v1 compose test rules run effects inline.** An effect that calls `navigate` can then run before a `Scaffold` has composed its `NavHost`, which fails with "Navigation graph has not been set". Activity tests that start from a deep link need the `junit4.v2` rules, which queue effects as production does.
- **A non-inclusive `popUpTo` with `saveState` files the saved stack under the `popUpTo` target.** Add `restoreState` to the same call and a screen pushed over the start destination comes straight back. Ordinary tab switching escapes only because its first pop saves nothing (review finding 43). The fix: going to the start destination is `popBackStack(start, inclusive = false, saveState = true)`, never `navigate` (`nav/TabNavigation.kt`). Send every top-level route through that one helper.
- **`launchSingleTop` on the visible destination swaps its entry for a copy, and the copy can stay at CREATED.** Every `collectAsStateWithLifecycle` and `repeatOnLifecycle` on that screen then goes silent: state changes, the UI does not. In `NavController.navigate` the `launchSingleTop` branch only runs when the restore branch does not, so changing `restoreState` can expose it. `TabNavigationLifecycleTest` pins the entry at RESUMED on a stub `NavHost`.
- **Run the whole suite before trusting a navigation change.** The targeted tests for finding 43 were green while the app was broken. A test from the previous fix caught it, because it happened to close a sheet after a deep link.
- **Prove a guard test by mutation.** A test that pins existing behavior passes on the first run, which proves nothing. Break the behavior on purpose, watch the test fail, and revert.
- **Wait for the state a test is about, not for the screen.** The doubled Matrix entry arrives a moment after the first frame. A Back press sent too early passes against broken code. Wait on `pendingRoute` clearing first.
- **Shared UI requests are events, not state.** A `StateFlow` replays its value to every new collector, and a composition restarts its collectors on every tab switch and rotation. Use `OneShotRequest` (claim with `compareAndSet`) and consume through `ConsumeWhileStarted`.
- **Validate what the user types, where they type it.** A state change to a stored task must never reject it, because sync can deliver a task that breaks a local limit. iOS counts characters, while the web and Android count UTF-16 units, so one emoji is enough. Use `TaskStore.change`, `duplicate`, or an intent method for state changes. Keep `add` and `update` for typed input (review finding S6).
- **Check the siblings before trusting the spec on shared behavior.** Spec 7.11 said "every write path", and Android followed it. Neither the web nor iOS validates on a state change. When two shipped clients agree and the spec disagrees, the spec is the outlier.
- **An uncaught exception in `viewModelScope` kills the instrumentation process.** The run ends with "Process crashed" and the later tests never run. That is a faithful reproduction of a user-facing crash, and it is why a view model test for a crash bug belongs in its own targeted run while red.
- **Write the reproduction before the design question.** A failing test that holds under every candidate design costs nothing to keep, and it turns the design proposal from an opinion into evidence.
- **A Back key in a test depends on two things the test does not own.** A text field that takes focus in a dialog raises the soft keyboard, and Back then hides the keyboard and leaves the dialog open. A key sent while a closing dialog is still handing input focus back is dropped. Prefer a semantics action. When the test is about Back itself, wait for `mInputShown=false` in `dumpsys input_method` and for `Activity.hasWindowFocus()`.
- **A test that has passed for a day can still be a race.** `PaletteRequestsTest` went from passing every run to failing every run once the keyboard process was warm. Timing the test does not control is luck, in either direction.
- **An activity's window insets do not report a keyboard that belongs to a dialog's window.** Ask the system instead: `uiAutomation.executeShellCommand("dumpsys input_method")`.
- **Shell calls in diagnostics change the timing they are measuring.** Two `dumpsys` calls before a key press hid the race for six runs. Log cheap in-process facts before the event and the expensive ones after it.
- **Read inside the transaction you write in.** `get(id)` followed by `withTransaction { write }` lets two callers act on the same stale read. Room runs transactions one at a time, so a read inside one is the ground truth. Eight concurrent completes spawned eight instances until `setCompleted` moved its read (review finding S5).
- **A state setter should do nothing when the state already matches.** Writing anyway restamps `updatedAt`, queues a push, and can win last-write-wins over a newer edit made elsewhere. It also overwrites facts like `completedAt`. Compare first, then write.
- **Make a race test fail on purpose.** Two concurrent calls can pass by luck against broken code. Eight made the red run certain.
- **A green review check can mean that no review ran.** The Claude review workflow finished in 15 seconds with 5 turns on four of seven pull requests, because its `--allowedTools` denies the plugin's first `gh` call. Read `num_turns` and `duration_ms` in the run log before you trust a clean result. A real review here took 6 to 9 minutes.
- **Stacked pull requests merge cleanly with merge commits.** Base each PR on the branch below it, so each diff and each review covers one change. Merge bottom-up, retarget the next PR to `main`, and wait until `mergeable` leaves `UNKNOWN`. A squash or a rebase would change the SHAs and force a rebase of everything above.
- **STARTED does not mean the user can see it.** A covered activity stays STARTED until the new one is up, so a STARTED gate lets the hidden instance win a race with the visible one. When two instances can exist, scope shared requests to the instance, or gate on RESUMED.
- **A fix made under review needs its own red test, and the test needs rechecking after the next fix.** My stale-cursor test built its state with `LocalErase`. The next commit made `LocalErase` clear the cursor, and the test passed with the code under test deleted. Build the state directly, and prove the test by removing the line it guards.
- **The cursor belongs to the data it describes.** A pull cursor means "everything up to here is on this device". Any code that erases the tasks must clear the cursor in the same transaction, or a later step can be skipped and leave a wiped device that never pulls its history again.
- **`singleTop` is not enough when another page can sit above the activity.** The sign-in Custom Tab runs in GSD's task, above `MainActivity`. `singleTop` reuses an activity only at the top of its task, so the OAuth callback would still stack a copy. `singleTask` closes what is above and hands the link to the one instance (review finding 4).
- **Test a launch mode by counting instances.** `ActivityLifecycleMonitorRegistry` lists every live activity by stage. Wait for either outcome: a second copy, or the handled link. The red run then fails on `expected 1 but was 2`, not on a timeout.
- **Static shortcuts restart the task.** `dumpsys shortcut` shows `flg=0x1000c000` on both: `NEW_TASK`, `CLEAR_TASK`, and `TASK_ON_HOME`. They never reach `onNewIntent`, they discard an open draft, and the app cannot change those flags.
- **Check every caller before wiring a dead control.** The "..." button had an empty lambda, and three of the six surfaces that draw a card had no menu to open. A control with nothing behind it should not be drawn (review finding 1).
- **An `else` in a `when` over an enum hides the value you forgot.** `SwipeTaskRow` gave the resting state the red delete background that way, and Trash drew its text on it (review finding 2). Name every value, and let the compiler ask about the next one.
- **A pixel test needs content that paints nothing.** An opaque card hid the resting background on Matrix. `captureToImage().toPixelMap()` over a bare `Spacer` showed it in one run. Read the expected colors from the theme inside the composition.
- **Fix a branch in the middle of a stack from a separate worktree.** `git worktree add <scratch> <branch>` leaves the main tree alone, which matters when reviewers or a build are reading it. `git merge-tree --write-tree` then shows whether the branches above still merge cleanly.
